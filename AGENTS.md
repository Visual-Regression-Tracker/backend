# AGENTS.md — VRT backend

Rules for AI agents (and humans) working in this repo. **The first rule:** before
building anything, look for how the project already does it — a script in
`package.json`, a generator, an existing module or pattern — and use that. Do not
hand-roll what a project tool produces.

## Stack

NestJS · Prisma (PostgreSQL) · Jest · worker threads for image work. Node `>=24.15`.

## Database: Prisma only

- The schema is `prisma/schema.prisma`. The client is generated into
  `node_modules/.prisma/client` (`npm i` runs `prisma generate`; after editing the
  schema run `npx prisma generate`).
- **Migrations are generated by Prisma, never written by hand.** After changing
  the schema:
  1. `docker compose up -d postgres` (dev DB; credentials in `.env`),
  2. `npx prisma migrate dev --name <snake_case_description>`.

  This creates `prisma/migrations/<timestamp>_<name>/migration.sql`. Commit it
  together with the schema change. If no database is reachable, stop and ask —
  do not write or "reconstruct" `migration.sql` yourself.
- Never edit a migration that is already in `prisma/migrations`; add a new one.
- `prisma format` realigns the whole model block it touches — expected, keep it.
- Migrations reach environments through the `migration` service
  (`prisma/` is its own package, `prisma/entrypoint.sh` runs
  `prisma migrate deploy` then the seed). Do not apply schema changes any other way.
- A new non-nullable column needs a `@default(...)` so existing rows migrate.

## Code conventions

- Tests live next to the code as `*.spec.ts`. New code is covered; the coverage
  thresholds are part of the build.
- CPU-bound image work (PNG decode, diffing, blurring) runs in `DiffWorkerPool`
  as a `kind`-discriminated job (`src/compare/libs/pixelmatch/worker-job.ts`),
  never on the event loop. Job input/output must be structured-clone serializable.
- Comparators implement `ImageComparator`
  (`src/compare/libs/image-comparator.interface.ts`); `CompareService` picks one
  per project. Comparator-agnostic behaviour belongs in `CompareService`.
- API input is validated by DTOs (`class-validator`, global `ValidationPipe`).
  Fields older clients do not send must be `@IsOptional()`, or saving breaks for them.
- Format only the files you changed (`npx prettier --write <files>`), not whole
  directories: prettier also rewrites untouched files, markdown included.
- Comments: by default, none. Write one only for a non-obvious _why_ that a
  reader would otherwise get wrong, and keep it to one line. Delete on sight:
  comments that restate the code or its names, narrate past bugs or earlier
  versions (that goes in the commit message), explain what a well-named
  function already says, point at review notes or ticket ids that are not in
  the repo, or run for several lines without changing what a reader would do.
  No TODOs or "known issue" notes (open an issue). Tests follow the same rule:
  the test name says what is checked. Match existing naming. Before a pull
  request, see the `pre-pr-review` skill.

## Services beside the API

- ML runs in separate services the API reaches over HTTP, configured by env:
  Ollama for VLM (`OLLAMA_BASE_URL`), DINOv2 for the rendering-noise filter's
  `dinov2Check` (`DINOV2_URL`, `dinov2/` in this repo, compose profile
  `dinov2`). Do not load models into the API process or its workers.
- `dinov2/` is Python: `python -m unittest test_patches` there; the image
  pins the model revision the backend's threshold was calibrated on.

## Known quirks — do not "fix" in passing

- `PixelmatchService` passes `includeAA: config.ignoreAntialiasing`; in pixelmatch
  `includeAA: true` *counts* anti-aliased pixels. Inherited from upstream and
  pinned by tests; changing it alters every project's results — a separate decision.
- The DTO/property `diffTollerancePercent` is misspelled throughout and is part of
  the public API. Keep the spelling.
